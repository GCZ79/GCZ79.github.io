Algorithms & Data Structures Enhancement

The algorithms and data structures enhancement focused on improving the performance and scalability of the Grazioso Salvare Animal Rescue Dashboard. The original application relied heavily on client-side processing, which created performance limitations as the dataset increased.

The enhancement introduced more efficient data retrieval strategies by moving processing responsibilities to the database layer and implementing optimized data structures for frequently accessed information.

Performance Challenges Identified

The original application had several performance limitations:

  • Large amounts of data processing occurred on the client side.
  • Database queries relied primarily on collection scans.
  • Pagination required transferring unnecessary records.
  • Frequently requested filters repeated identical database operations.

These limitations affected response time and reduced scalability as the dataset size increased.

Implemented Algorithm Improvements

MongoDB Compound Indexes

Implemented compound indexes on frequently queried fields:

  • animal_type
  • breed
  • sex_upon_outcome
  • age_upon_outcome_in_weeks

Indexes improve query efficiency by reducing the amount of data MongoDB must scan when retrieving matching records.

Aggregation Pipelines

Moved filtering and data transformation operations from the frontend to MongoDB aggregation pipelines.

Operations such as matching, projection, grouping, and sorting are now performed closer to the data source, reducing unnecessary data transfer.

Server-Side Pagination

Implemented pagination using MongoDB skip() and limit() operations.

This allows the application to retrieve only the records required for the current page instead of loading the entire dataset.

LRU Cache Implementation

Added a Least Recently Used (LRU) cache using JavaScript Map to store frequently accessed rescue and training filter results.

The cache improves response times for repeated requests while limiting memory usage through a fixed capacity.

Data Structure Design

The LRU cache uses a JavaScript Map data structure to maintain recently accessed values. When a cached item is accessed, it is moved to the most recent position. When the cache reaches capacity, the least recently used entry is removed.

This approach provides efficient lookup and update operations while preventing uncontrolled memory growth.

Complexity Analysis

  • MongoDB indexed queries reduce lookup complexity compared with full collection scans.
  • LRU cache retrieval provides approximately O(1) lookup performance through Map-based storage.
  • Server-side pagination reduces unnecessary processing by limiting returned records.
  • Aggregation pipelines improve efficiency by processing data before it reaches the application layer.

Performance and Scalability Trade-offs

The implemented improvements increase application performance and scalability, but introduce additional design considerations.

  • Indexes improve query speed but require additional database storage.
  • Caching improves response time but requires cache invalidation strategies.
  • Server-side pagination improves scalability but adds backend complexity.
  • Aggregation pipelines improve efficiency but require careful query design.
